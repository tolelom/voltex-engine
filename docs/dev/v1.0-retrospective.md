**Date**: 2026-05-21
**Tag**: `v1.0.0`
**총 사이클**: 15 (Cycle 1~15) + AI 친화 재구조화 M1~M7 + Phase 1~8 (pre-roadmap)

## 무엇이 성공했나

### 1. "외부 crate 의존 2개" 정책의 유지

런타임 의존이 끝까지 `winit` + `wgpu` 두 개로 묶였다. 이미지/메시 파서,
오디오 디코더, GUI, TTF, 폰트 아틀라스, asset packing, manifest parser, mini
TOML parser — 모두 자체 구현. Phase 2 의 PNG/JPG 부터 Cycle 8 의 voltex.toml
파서까지 일관됨.

### 2. AI 친화 재구조화 (M1~M7) 가 후속 작업을 끌어올림

15 개 cycle 의 평균 세션 길이가 짧고, 컨텍스트 전환이 빠른 이유:

- 모든 crate 에 `CODEMAP.md` — 위치 1회 조회로 책임 + API + 의존성 파악
- 모든 `.rs` 파일 600줄 이하 — 단일 `Read` 로 파일 1개 정복
- `thiserror` 기반 `<Crate>Error` + `Result<T>` alias — crate 간 에러 전파가 `?` 한 줄
- `voltex` facade + `prelude` — `use voltex::prelude::*;` 한 줄로 시작

Cycle 4 의 spec 작성부터 Cycle 15 의 voltex_survivor 까지 전부 이 베이스
위에서 돌아갔다.

### 3. Slice 1~3 의 시퀀스가 의도대로 굴러감

| Slice | Cycle | 결과 |
|---|---|---|
| **1 — MVP end-to-end** | C0a / C0b / E1 / E2 / S1 / B0 / B1-spike / B1 / B2 | Windows 한 OS 에서 editor → script → build → 단일 exe 배포까지 동작 |
| **2 — 플랫폼 broaden** | P1 / B3 / (E3 flex) | AudioBackend trait + ALSA + CoreAudio (코드 작성 단계), 멀티 OS native-only 빌드 정책 + 친화 에러 |
| **3 — 외부 사용자 onboarding** | A / D1+D2 / D3 | rustdoc 0 워닝 + prelude 완성 + CHANGELOG, README + 30분 튜토리얼 + tutorial_minigame, flagship survivor 게임 |

### 4. 게임 로직의 100% Lua 검증 (Cycle 15)

`voltex_survivor` 의 게임플레이 (이동 발사 / 적 AI / 점수 / lives / wave) 가
4개 `.lua` 파일 약 200줄에 들어간다. Rust 측은 부트스트랩 + 입력 → Transform
+ 메시 핸들 자동 부착의 3 가지 boilerplate 만 담당. 외부 사용자가 따라할 수
있는 패턴이 검증됨.

cross-LuaState 메시지 전달은 "Tag 기반 marker entity 메일박스" 패턴으로
해결: projectile.lua 가 enemy 처치 시 `kill_marker` entity 를 spawn 하고,
game.lua 가 `iter_by_tag("kill_marker")` 로 수확 후 destroy. 깔끔하지는 않으나
ScriptInstancePool 의 path-per-LuaState 모델을 그대로 살리는 우회.

## 무엇이 v1.1 로 미뤄졌나

### 1. Full `#![warn(missing_docs)]` sweep (Cycle 13 의 명시 deferral)

`-W missing_docs` 측정 시 누락 **1586 항목**. v1.0 은 prelude + tier-1 API
(World/Entity/EditorCommand/EditorSession + 핵심 메서드) 만 docstring 보장.

대안 — `cargo doc --workspace --no-deps` 는 워닝 0 으로 통과. rustdoc HTML
사이트는 정상 생성됨. 누락 항목은 점진 추가.

### 2. 실 머신 검증 (Cycle 10 / 11 / 15)

- **ALSA backend** (Linux) — Windows 호스트에서 작성, `cargo check --target x86_64-unknown-linux-gnu` 통과. 실제 audio_demo 소리 출력 검증 X.
- **CoreAudio backend** (macOS) — 동일 상황. `cargo check --target aarch64-apple-darwin` 통과만.
- **3 OS exe 산출** — Mac / Linux 머신에서의 `voltex build --target X` 실 검증은 사용자 PR 로 처리.

### 3. Lua 측 input API

v1.0 의 voltex_survivor 는 입력을 Rust 의 `add_input_system` 으로 처리.
Lua engine_api 가 InputState 를 노출하지 않음. v1.1 의 후속 — `input.is_key_pressed("W")`
같은 API.

### 4. CLI 의 에디터 모드

`voltex_cli` 는 `new` / `build` / `run` 만. 로드맵 § 1.2 의 `voltex_cli --bin
voltex_editor` 는 미구현. 튜토리얼은 `examples/editor_demo` 로 에디터를 안내.

### 5. `pub(crate)` 다운그레이드 실행

`docs/dev/v1.0-pub-audit.md` 에 후보 노트만 작성. 실제 변경은 v1.1 의 첫 작업.

### 6. 스크린샷 + 비디오 튜토리얼

README + tutorial 의 `<screenshot: ...>` 플레이스홀더 6~10 개. 사용자 머신
캡쳐 + PR 환영.

### 7. 멀티 셀렉트 / Undo of large reorderings / asset compression / WebGPU+WASM / mobile

로드맵 § 6.3 의 항목들 그대로. v1.1 이후 진행.

## 닫는 말

5 주 가량의 작업이 15 개 의도된 cycle 로 끝난다. spec → plan → impl → verify 의
표준 4 단계가 매 cycle 일관되게 적용되었고, 모든 산출물 (spec / plan / commit
hash / done 기준) 이 `docs/superpowers/` 에 보존됨 — 외부 사용자가 "어떻게
여기까지 왔는지" 추적 가능.

v1.0 는 "단일 OS exe 산출 + 외부 사용자가 따라할 수 있는 패턴 검증"이
달성점. 멀티 OS 검증 + scope deferred 항목들은 v1.1 의 일.

— Voltex Engine team, 2026-05-21
